# Rachata Plus: เริ่มอ่าน React จากหน้าที่เราสร้าง

## เปิดเว็บในเครื่อง

เปิด Terminal ที่ `C:\Users\User\Desktop\rachata-plus\apps\web` แล้วรัน:

```sh
npm run dev
```

เปิด URL ที่ Vite แสดงใน Terminal โดยปกติคือ `http://localhost:5173`
ถ้ามี dev server เปิดอยู่แล้ว ใช้หน้าที่เปิดอยู่ได้เลย ไม่ต้องรันซ้ำ

## ตอนนี้ทำอะไรได้

- หน้าแรก → เลือกการ์ด → รายละเอียด → หน้ารับชม
- วิดีโอทั้งหมด และปุ่มดูภายหลังที่จำแยกแต่ละวิดีโอ
- หน้าแอดมิน: เลือกไฟล์ กรอกข้อมูล ยกเลิก/จำลองอัปโหลด และเพิ่มการ์ดตัวอย่าง
- โปรไฟล์: แก้ชื่อกับอีเมล บันทึก หรือยกเลิก
- หน้าเข้าสู่ระบบ `#/login` และสร้างบัญชี `#/register` พร้อมตรวจข้อมูลและแสดง/ซ่อนรหัสผ่าน
- ทดลองสมัคร → หน้าผลลัพธ์ → เข้าสู่ระบบตัวอย่าง → โปรไฟล์บัญชีทั่วไป → ออกจากระบบ
- บัญชีฟรีดูรายละเอียดและเปิดเครื่องเล่นตัวอย่างฟรีได้ แต่กดดูเต็มเรื่องแล้วจะพบหน้าเลือกแพ็กเกจ
- หน้าแพ็กเกจ `#/plans`: เปรียบเทียบ Free / Basic / Standard / Premium และยืนยันเปิดสิทธิ์เดโม่โดยไม่ชำระเงินจริง
- Skeleton ช่วงเปลี่ยนหน้า เปิดค้างได้ที่ “โหมดทดลอง UI” ด้านล่าง
- เริ่มต้นเป็นผู้เยี่ยมชม เปลี่ยนสิทธิ์ตัวอย่างเป็นบัญชีทั่วไป สมาชิกแบบชำระเงิน หรือแอดมินได้ในแถบเดียวกัน

ข้อมูลอยู่ใน React state เท่านั้น เมื่อรีเฟรชจะกลับค่าเริ่มต้น ยังไม่มีการส่งไฟล์
การเล่นวิดีโอจริง ล็อกอิน ชำระเงิน หรือบันทึกลงฐานข้อมูล
การเลือกสิทธิ์ด้านล่างเป็นเครื่องมือดูหน้าจอ ไม่ใช่ระบบยืนยันตัวตน
ฟอร์มเข้าสู่ระบบตรวจเฉพาะความครบถ้วน ไม่ได้ตรวจว่ารหัสผ่านตรงกับบัญชีจริง
รหัสผ่านถูกล้างก่อนจำลองผลลัพธ์ ไม่ส่งให้ App ไม่เก็บใน storage และไม่ส่งไป API
บัญชีทั่วไปที่ทดลองเข้าสู่ระบบยังไม่มีสิทธิ์ดูวิดีโอสำหรับสมาชิกแบบชำระเงิน
เมื่อยืนยันแพ็กเกจเดโม่ จะเปิดสิทธิ์สมาชิกใน React state และกลับไปวิดีโอเรื่องที่กดไว้
ชื่อแพ็กเกจที่เลือกแสดงในโปรไฟล์ด้วย การรีเฟรช/ออกจากระบบจะล้างสิทธิ์นี้
ราคาจริงยังไม่กำหนด ส่วนความละเอียดและจำนวนอุปกรณ์ในการ์ดเป็นข้อมูลตัวอย่างสำหรับออกแบบ

## อ่านไฟล์ตามลำดับนี้

3. `src/components/UI.tsx` — ชิ้นส่วนที่ใช้ซ้ำ เช่น Skeleton และการ์ดวิดีโอ
4. `src/pages/Browse.tsx` — หน้าแรก รายการวิดีโอ และรายละเอียด

6. `src/pages/UploadPage.tsx` — ฝึกสถานะหลายขั้นและ cleanup timer

9. `src/pages/AuthPage.tsx` — ฟอร์มเข้าสู่ระบบ/สร้างบัญชี การตรวจข้อมูล และสถานะกำลังส่ง
10. `src/data/plans.ts` — ข้อมูลแพ็กเกจที่ใช้วาดการ์ดเปรียบเทียบ

## บทแรก: Component และ props

Component คือฟังก์ชันที่คืน JSX เพื่อบอก React ว่าจะแสดงอะไร:

```tsx
export function Skeleton({ shape }: { shape: string }) {
  return <div className={`rp-skeleton rp-sk-${shape}`} aria-hidden="true" />
}
```

เรียกใช้ `<Skeleton shape="title" />` แล้ว `shape` จะมีค่า `title`
ข้อมูลที่ส่งเข้า component แบบนี้เรียกว่า **props**
ส่วน `{ shape: string }` คือ TypeScript ที่ระบุว่าค่านี้ต้องเป็นข้อความ

## บทสอง: State ทำให้หน้าจอเปลี่ยน

ใน `WatchPage.tsx`:

```tsx
const [playing, setPlaying] = useState(false)
```

- `playing` เป็นค่าปัจจุบัน เริ่มต้นเป็น `false`
- `setPlaying` เป็นฟังก์ชันเปลี่ยนค่า
- `setPlaying(!playing)` สลับจาก false → true หรือ true → false
- React แสดงข้อความและปุ่มใหม่ตามค่า state เราไม่ต้องสั่งแก้ DOM เอง

## บทสาม: ฟอร์มแก้โปรไฟล์

`ProfilePage.tsx` มีข้อมูลสองชุด:

- `profile`: ข้อมูลที่กดบันทึกแล้ว ส่งมาจาก App ผ่าน props
- `draft`: ข้อมูลที่กำลังพิมพ์ ยังไม่บันทึก

เมื่อกดแก้ไข จะคัดลอก profile ไป draft เมื่อพิมพ์จะเปลี่ยน draft เท่านั้น
ปุ่มบันทึกเรียก `onSave(draft)` ให้ App เปลี่ยนข้อมูลจริงของตัวอย่าง
ปุ่มยกเลิกทิ้ง draft จึงไม่ทำให้ profile เปลี่ยน

นี่คือเหตุผลที่เราแยกข้อมูลที่กำลังแก้ออกจากข้อมูลที่บันทึกแล้ว

## ฟอร์มเข้าสู่ระบบและสร้างบัญชีทำงานอย่างไร

`AuthPage` รับ prop `mode` เพื่อเลือกหน้าล็อกอินหรือสมัครบัญชี และใช้ `PasswordField`
ซ้ำสำหรับช่องรหัสผ่านกับช่องยืนยัน แต่ละช่องมี state แสดง/ซ่อนของตัวเอง

เมื่อกดส่ง `submit()` จะตรวจชื่อ อีเมล รหัสผ่าน และคำยืนยัน แล้วเก็บข้อความแจ้งเตือน
ไว้ใน `errors` เพื่อแสดงใต้ช่องที่ผิด พร้อมย้ายโฟกัสไปช่องแรกที่ต้องแก้
ความยาวรหัสผ่านสมัครบัญชี 15–128 ตัวอักษรสอดคล้องกับ handler ฝั่ง Go ที่มีอยู่

เมื่อฟอร์มผ่าน จะจำลองการรอ 700 มิลลิวินาทีแล้วเรียก callback ใน App:

- `onRegisterPreview(name, email)` จำเฉพาะชื่อและอีเมลตัวอย่างในหน่วยความจำ
- `onLoginPreview(email)` เปิดโปรไฟล์ตัวอย่างด้วยสิทธิ์บัญชีทั่วไป

การตรวจหน้าบ้านช่วยเรื่อง UX แต่ระบบจริงยังต้องตรวจทุกอย่างอีกครั้งบน Go API
ฝั่ง Go ปัจจุบันมี `/auth/register` แต่ยังไม่มี endpoint เข้าสู่ระบบ

## ทำไมใช้ URL ที่มี #

เช่น `#/profile` และ `#/watch/1` เป็น hash routing แบบเล็ก ๆ ใน App
จึงกดลิงก์ ย้อนกลับ และรีเฟรชหน้าเดิมได้ โดยไม่ต้องเพิ่มแพ็กเกจ router
ถ้ารีเฟรชหน้าวิดีโอที่เพิ่งสร้างจำลอง วิดีโอนั้นจะหาย เพราะยังไม่ได้บันทึกจริง

## ขั้นต่อไปเมื่อพร้อมเชื่อมระบบ

- เชื่อมรายการและรายละเอียดวิดีโอกับ Go API
- ทำล็อกอินและตรวจสิทธิ์บน Go API ทุก endpoint ที่ต้องใช้สิทธิ์
- อัปโหลดจริงด้วย URL ที่ backend ออกให้ และติดตามสถานะประมวลผล
- ใช้ URL สตรีมจริงในเครื่องเล่น
- บันทึกโปรไฟล์และยืนยันอีเมลผ่าน backend
- ออกแบบ migration สำหรับหมวดหมู่/ระยะเวลา ถ้าจะใช้ตาม UI นี้
- ลบเครื่องมือเลือกสิทธิ์จำลองก่อนนำไปให้ผู้ใช้จริง
- ตรวจสถานะสมาชิกและสิทธิ์เข้าถึงไฟล์จริงที่ backend; `viewer` ใน React เป็นเพียงการจำลองหน้าจอ
