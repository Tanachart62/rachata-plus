# Accessibility — Rachata Plus UI

ปรับและตรวจเมื่อ 5 ตุลาคม 2026 โดยใช้ WCAG 2.2 ระดับ AA เป็นเป้าหมาย
เอกสารนี้เป็นบันทึกการแก้และทดสอบ UI เดโม่ ไม่ใช่ใบรับรองว่าผ่านทุก Success Criterion

## ขอบเขตทุกหน้า

| หน้า | สิ่งที่ปรับหรือตรวจ |
| --- | --- |
| หน้าแรก / วิดีโอทั้งหมด | main landmark, ชื่อหน้า, ลิงก์การ์ด, Skeleton, keyboard focus |
| รายละเอียดวิดีโอ | รวมเนื้อหาใน main, แท็บแบบ roving tabindex, ลูกศร/Home/End, disclosure ตัวอย่าง |
| รับชม | ปุ่มและ slider ใช้คีย์บอร์ด, อ่านตำแหน่งเป็นนาที/วินาที, ปุ่มขนาด 44px, controls ไม่ทับข้อความ |
| ค้นหา / ไม่พบผลลัพธ์ | ชื่อช่องค้นหา, ปุ่มล้าง/ค้นหา, focus ที่เนื้อหาหลังนำทาง, แจ้งจำนวนผลลัพธ์ |
| สมัคร / เข้าสู่ระบบ | labels, autocomplete, คำแนะนำ, ข้อผิดพลาดรายช่อง, focus ช่องแรกที่ผิด, สถานะนอก aria-busy |
| โปรไฟล์ / เปลี่ยนรหัสผ่าน | autocomplete name/email, validation, focus เข้า/ออกฟอร์ม, tabs, ปุ่มแสดงรหัสผ่านไม่ทับช่องเมื่อขยายข้อความ |
| แพ็กเกจ / ยืนยัน | native radios, สถานะเลือกที่มีข้อความ, focus ขั้นยืนยันและกลับไปเลือก, สถานะเปิดสิทธิ์ |
| ประวัติการรับชม | ชื่อลิงก์รวมชื่อวิดีโอ, แจ้งผลตัวกรอง, progress ที่อ่านค่าได้ |
| จัดการวิดีโอ | แยกชื่อคำสั่งแต่ละวิดีโอ, modal Tab/Shift+Tab/Escape, คืน focus หลังยกเลิก/ลบ/กรอง |
| อัปโหลด | เลือกไฟล์ได้โดยไม่ต้องลาก, errors ผูกกับช่อง, focus ช่องแรกที่ผิด, ยกเลิก/สำเร็จ/เริ่มใหม่ |
| Dashboard | ตารางข้อมูลแทนกราฟ, keyboard scrolling ในตาราง, แจ้งการเปลี่ยนช่วงข้อมูล, retry และ focus |
| หน้าไม่มีสิทธิ์ / ไม่พบหน้า | หัวเรื่อง, ชื่อหน้า, ทางกลับที่ชัดเจน และไม่ประกาศ loading ค้าง |

ส่วนร่วม: ลิงก์ข้ามไปเนื้อหา, focus ที่มองเห็นได้, ไม่แย่ง focus จากช่องที่กำลังพิมพ์เมื่อโหลดเสร็จ, lang=th และระบุวลีภาษาอังกฤษ, reduced motion, Windows forced colors, สีข้อความและขอบช่องกรอก

- 1.4.3, 1.4.11: contrast ข้อความ/ขอบช่องกรอก/สถานะที่สำคัญ
- 1.4.4, 1.4.10, 1.4.12: ขยายข้อความ, reflow และ text spacing
- 2.1.1, 2.1.2: ใช้คีย์บอร์ดได้และออกจาก dialog ได้
- 2.4.1–2.4.4, 2.4.6–2.4.7, 2.4.11: ข้ามส่วนซ้ำ, ชื่อหน้า, ลำดับและตำแหน่ง focus, ป้ายกำกับ
- 2.5.3, 2.5.7–2.5.8: ชื่อปุ่มตรงกับสิ่งที่เห็น, ทางเลือกการลากวาง, ขนาดเป้าหมาย
- 3.1.1–3.1.2, 3.3.1–3.3.3: ภาษา, คำแนะนำและข้อผิดพลาด

- 4.1.2–4.1.3: name/role/value และข้อความสถานะ

Playwright + headless Google Chrome ผ่านการอัปโหลด/เผยแพร่, เปิดตัวอย่าง, เล่นและ seek วิดีโอเต็ม, reload, บัญชีฟรีเข้าแพ็กเกจ, ซ่อนและลบ

หมายเหตุระบบบัญชีรอบถัดมา (5 ตุลาคม 2026): สมัครและล็อกอินเชื่อม API ในเครื่องแล้ว
ผลทดสอบ 30 กรณีด้านล่างเป็นผลรอบ UI เดโม่เดิม ไม่ใช้แทนการตรวจ authentication flow ใหม่
flow ใหม่คง labels, autocomplete, field errors และเพิ่มข้อความ API error พร้อมย้ายโฟกัส; ยังต้องตรวจ screen reader/zoom จริงตามข้อจำกัดเดิม
Playwright + headless Google Chrome: สมัครจริง, ล็อกอินผิด/ถูก, focus ข้อผิดพลาด, session หลังรีเฟรช, logout, ชื่อผู้ใช้/อีเมลซ้ำ และ network error ผ่าน
ตรวจโปรไฟล์ที่ 320/768/1440 CSS px ไม่พบ page overflow ในรอบนี้; ยังไม่ได้ตรวจทุกหน้าใหม่หรือใช้ผลนี้อ้าง WCAG ครบ

- `npm run build` และ `npm run lint` ผ่าน
- Playwright + headless Microsoft Edge: 15 URL/สถานะ × ผู้เยี่ยมชมและแอดมิน รวม 30 กรณี
- ทุกกรณีมี main และ h1 หนึ่งรายการหลังโหลด, ชื่อหน้าเหมาะกับเนื้อหา และ aria references ชี้องค์ประกอบที่มีอยู่
- ไม่พบ horizontal page overflow ที่ viewport 320, 768 และ 1440 CSS px
- ทดสอบ Tab/Shift+Tab/Escape ใน dialog, คืน focus หลังลบ/ยกเลิก, tabs Home/End, ค้นหา, profile validation, upload และยกเลิก/เริ่มใหม่, review/back, retry, slider, ประวัติ
- ทดสอบบัญชีฟรีเปิดแพ็กเกจแล้วกลับสู่เครื่องเล่น, สมัครและเปลี่ยนรหัสผ่านทั้ง invalid/success, พิมพ์ระหว่าง loading โดย focus ไม่ถูกดึงกลับ
- ตรวจ text spacing (line-height 1.5, paragraph 2em, letter .12em, word .16em) ที่ 320px และจำลองขยาย font-size 200% ที่ 1280px ใน 8 หน้าหลัก ไม่พบ page overflow
- ตรวจภาพหน้าจอสมัครสมาชิกที่ขยายข้อความ/ปรับ spacing, เครื่องเล่นบนมือถือ และ dialog ใน forced colors
- ตรวจข้อความบนพื้นสีทึบด้วยสูตร luminance ไม่พบคู่ที่ต่ำกว่า 4.5:1 (หรือ 3:1 สำหรับข้อความใหญ่) ในกรณีที่สคริปต์ประเมินได้; สคริปต์ข้ามพื้น gradient/opacity จึงไม่ใช้ผลนี้อ้างว่าทุก pixel ผ่าน
- ปุ่มหลักขาวบน #cf243c ประมาณ 5.29:1; ขอบ input #788399 บน #0f1219 ประมาณ 4.91:1
- Skeleton หยุด animation เมื่อ prefers-reduced-motion: reduce

## วิธีตรวจซ้ำด้วยมือ

1. ใช้ Tab จากต้นหน้า เปิด skip link แล้วเดินทุกปุ่ม/ช่องโดยไม่ใช้เมาส์
2. ใน modal ลบ: Tab วนภายใน, Shift+Tab ย้อน, Escape กลับปุ่มเดิม; ยืนยันลบกลับหัวเรื่องคลัง
3. ใช้ลูกศร/Home/End บนแท็บ และตรวจว่า Tab เข้าสู่แท็บที่เลือกเพียงตัวเดียว
4. ส่งฟอร์มว่าง แล้วอ่านข้อผิดพลาดรายช่อง; แก้และส่งใหม่ รวมการยกเลิก
5. เปิดข้อมูลตารางใน Dashboard แล้วใช้ PageDown/ลูกศรเลื่อนตาราง
6. ทดสอบ browser zoom จริง 200%/400%, NVDA + Edge/Firefox และ VoiceOver + Safari โดยอ่านหัวเรื่อง landmarks ฟอร์ม สถานะ และ dialog
7. ตรวจรูป/วิดีโอ/ข้อความจริงอีกครั้งเมื่อแทน placeholder และเมื่อเชื่อม API

## ยังต้องตรวจเพิ่มเติมก่อนอ้าง WCAG AA ทั้งระบบ

ยังไม่ได้ทำ screen-reader audit ด้วย NVDA/VoiceOver จริง, browser zoom จริงทุก flow, ตรวจหลายเบราว์เซอร์/อุปกรณ์ช่วยเหลือ หรือ audit ทุก Success Criterion อย่างอิสระ
การจำลอง font-size และ viewport ไม่เท่ากับการทดสอบ browser zoom จริง
เครื่องเล่นเชื่อม HLS จริงแล้ว แต่ยังไม่ได้ตรวจ captions, audio description และการเข้าถึงเนื้อหาวิดีโอจริงครบตามเกณฑ์
ก่อนใช้งานจริงต้องเตรียมสิ่งเหล่านี้ตามเนื้อหาของสื่อ รวมทั้งทดสอบสถานะผิดพลาดจาก API และระบบยืนยันตัวตนจริง

## ควบคุมบัญชี — 6 ตุลาคม 2026

เพิ่มสถานะบัญชีและคำสั่งระงับ/เปิดคืน/ออกจากระบบทุกอุปกรณ์ มีขั้นตอนยืนยัน โฟกัสหัวเรื่องยืนยัน และคืนโฟกัสปุ่มเดิมเมื่อยกเลิก ตรวจ Edge + Playwright ผ่านสำหรับคำสั่งจริงกับ 2 browser contexts, ข้อความ login บัญชีถูกระงับ, ปุ่มป้องกันระงับตัวเอง และหน้าจอ 320/768/1440 CSS px ไม่ล้น ยังไม่ได้ตรวจ screen reader จริง

## เซสชันรายอุปกรณ์ — 6 ตุลาคม 2026

เพิ่มรายชื่อเบราว์เซอร์/OS, เวลา login/หมดอายุ, marker เซสชันปัจจุบัน และตัดทีละเซสชัน มีชื่อปุ่มเฉพาะ ID, heading ยืนยัน, คืนโฟกัสเมื่อยกเลิก และโฟกัสหัวเรื่องรายการหลังตัด ตรวจ Edge + Playwright ผ่านกับ browser contexts ที่ระบุ User-Agent Edge/Windows และ Chrome/Android (ไม่ได้ทดสอบ Android เครื่องจริง), เซสชันอื่นยังใช้งานได้, self logout และ viewport 320/768/1440 ไม่มี horizontal overflow ยังไม่ได้ตรวจ screen reader จริง

## เซสชันในโปรไฟล์ผู้ใช้ — 6 ตุลาคม 2026

บัญชีฟรีและสมาชิกมีส่วนอุปกรณ์และเซสชันของฉัน ใช้ส่วนยืนยันและการจัดการโฟกัสร่วมกับแอดมิน ตรวจ Edge + Playwright ผ่าน: แสดงส่วนนี้สำหรับฟรี/สมาชิกและซ่อนสำหรับแอดมิน, ยกเลิกแล้วคืนโฟกัส, ตัดเซสชันอื่นแล้วอุปกรณ์นั้นเข้า API ไม่ได้แต่เซสชันปัจจุบันยังใช้ได้, ตัดเซสชันปัจจุบันแล้วต้องเข้าสู่ระบบใหม่ และไม่มีการล้นแนวนอนที่ 320/768/1440 CSS px การจำลองอุปกรณ์ใช้ browser contexts ไม่ใช่โทรศัพท์จริง ยังไม่ได้ตรวจ screen reader จริงหรือยืนยัน WCAG ครบทุกข้อ

## ภาพปกอัปโหลด — 6 ตุลาคม 2026

เพิ่ม file input ที่มี label/hint/error, ตัวอย่างภาพพร้อม alt, ปุ่มนำภาพออกและคืนโฟกัสช่องเลือกภาพ ตรวจ Edge + Playwright ผ่านสำหรับไฟล์ชนิดผิด, preview/remove/focus, อัปโหลดจริง, ภาพฉบับร่างไม่เปิดเผยต่อ guest, ภาพในคลังหลังเผยแพร่และโหลดใหม่ และ viewport 320/768/1440 CSS px ไม่ล้น ยังไม่ได้ตรวจ screen reader จริงหรือ WCAG ครบทุกข้อ

## เมนูคุณภาพ HLS — 6 ตุลาคม 2026

เครื่องเล่นมี native select ที่มี label และ ID เฉพาะแต่ละเครื่องเล่น แสดงอัตโนมัติ/ระดับจริงจาก manifest ปิดช่องขณะยังโหลดหรือเล่นผิดพลาด ตรวจ Edge + Playwright ผ่าน: เล่นที่ 360p/720p/480p จริง, เปลี่ยนระดับแล้วตำแหน่งไม่เริ่มใหม่, กลับอัตโนมัติ, viewport 320/768/1440 CSS px ไม่ล้น และขั้นตอนยกเลิก/ยืนยันแปลงใหม่ การตรวจ Docker ผ่านสำหรับ master/variant/segments ที่มีสิทธิ์ รวมถึง restart worker และ cleanup ยังไม่ได้ทดสอบ Safari/iPhone จริงหรือ screen reader จริง และไม่ยืนยัน WCAG ครบทุกข้อ

## แถบควบคุมเครื่องเล่นจริง — 6 ตุลาคม 2026

ย้ายคุณภาพมาอยู่กับแถบเวลาในเครื่องเล่น ใช้ปุ่มเล่น/พัก ปิด/เปิดเสียง slider เวลา/เสียง และเต็มจอของ wrapper เพื่อคงตัวเลือกคุณภาพไว้ตอนเต็มจอ ปุ่มมีชื่อและขนาดขั้นต่ำ 44px, slider มี label และเวลาที่อ่านได้, video ใช้ Space/Enter เล่นหรือพักและลูกศรซ้าย/ขวาเลื่อน 5 วินาที ตรวจ Edge + Playwright ผ่านกับวิดีโอจริง: เล่น/พัก, Home/ลูกศรบน slider, ปรับเสียง/ยกเลิก mute, 360p/720p, เข้า/ออกเต็มจอและเลือกคุณภาพในเต็มจอ, hit test ช่องคุณภาพและไม่มี horizontal overflow ที่ 320/768/1440 CSS px ยังไม่ได้ตรวจ screen reader หรือ Safari/iPhone จริง

## ยืนยันแพ็กเกจแบบจำลอง — 6 ตุลาคม 2026

แพ็กเกจเดิม/ต่ำกว่าใช้ radio disabled และมีข้อความบอกเหตุผล ขั้นยืนยันย้ายโฟกัสหัวเรื่อง กลับไปเลือกคืนโฟกัส radio ที่เลือก ปุ่มป้องกันส่งซ้ำและแจ้ง API error ตรวจ Edge + Playwright ด้วยบัญชีทดสอบชั่วคราว: Free → Basic → Standard → Premium, ยกเลิกก่อนยืนยัน, API ล้มเหลวไม่เปิดสิทธิ์แล้วลองใหม่ได้, สิทธิ์คงอยู่หลัง reload, ยับยั้ง downgrade ใน UI/API และ viewport 320/768/1440 CSS px ไม่ล้น การทดสอบนี้ไม่ใช่การเรียกเก็บเงินจริง และยังไม่ได้ตรวจ screen reader/zoom จริงหรือยืนยัน WCAG ครบ

## อัปโหลดรูปโปรไฟล์ — 6 ตุลาคม 2026

ปุ่มอัปโหลดมีคำแนะนำชนิด/ขนาดไฟล์ รูปมี alt พร้อมชื่อเจ้าของ ปุ่มปิดระหว่างส่ง แสดง error/status และคืนโฟกัสปุ่มหลังอัปโหลดหรือปฏิเสธไฟล์ ตรวจ Edge + Playwright: ไฟล์ผิดชนิด, PNG ที่เป็นข้อมูลปลอมถูก Backend ปฏิเสธและคงรูปเดิม, อัปโหลดจริงแล้วแสดง JPEG 256px, reload แล้วยังมีรูป, คืนโฟกัส และ viewport 320/768/1440 CSS px ไม่ล้น ยังไม่ได้ตรวจ screen reader หรือ browser zoom จริง และไม่ยืนยัน WCAG ครบ
